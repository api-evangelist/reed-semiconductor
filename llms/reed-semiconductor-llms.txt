# Reed Semiconductor

> Reed Semiconductor Corp. is a fabless power-management semiconductor company founded in 2019, headquartered in Rhode Island, USA, with offices in Taipei, Shenzhen and Bengaluru. "REED" stands for Robust, Efficient, Eco-friendly and Dense power solutions. It designs multiphase DC-DC controllers, smart power stages, half-bridge power stages, point-of-load converters, power modules, intermediate bus converters, eFuses and power multiplexers for data center and AI/HPC accelerators, 48V/12V distribution, communication and datacom equipment, automotive ADAS and infotainment, industrial systems and personal electronics.

## About this file

This llms.txt was generated by API Evangelist from probes of Reed Semiconductor's public
surface on 2026-08-26. Reed does not publish an llms.txt of its own — https://www.reedsemi.com/llms.txt
returns HTTP 200 carrying the site's HTML catch-all page, not a document.

Reed operates no developer program: there is no developer portal, no API documentation, no
OpenAPI, no SDK, no GitHub organisation and no status page. Everything below was found by
probing the WordPress/WooCommerce deployment that serves www.reedsemi.com. These endpoints
are real and live, but they are unannounced and uncommitted — treat them as best-effort.

## Agent surfaces

- [MCP server](https://www.reedsemi.com/wp-json/mcp/novamira-oauth): Model Context Protocol over JSON-RPC 2.0. OAuth-gated — an anonymous tools/list returns 401 with a WWW-Authenticate Bearer challenge. The tool list and input schemas are NOT public; do not assume any tool exists.
- [OAuth protected-resource metadata (RFC 9728)](https://www.reedsemi.com/.well-known/oauth-protected-resource)
- [OAuth authorization-server metadata (RFC 8414)](https://www.reedsemi.com/.well-known/oauth-authorization-server): Authorization-code with PKCE S256, refresh tokens, RFC 8628 device-code grant, RFC 7591 dynamic client registration. Single scope: mcp.
- [WordPress Abilities API](https://www.reedsemi.com/wp-json/wp-abilities/v1/abilities): OAuth-gated behind the same scope.

Not served: no A2A agent card at /.well-known/agent-card.json or /.well-known/agent.json,
no /.well-known/api-catalog, no /.well-known/security.txt, no ai-plugin.json. Each of those
paths returns HTTP 200 with an HTML page — the site answers 200 for every unmatched path, so
status code alone must not be read as presence.

## Caveats for agents

- Prices are meaningless. Every product returns prices.price "0" and is_purchasable false. WooCommerce is being used as a product catalog, not a storefront. Never quote a Reed part as free or as costing $0.
- There is no parametric search. Current rating, voltage, topology and package live as HTML prose inside the description field; the attributes array is empty on every product. Filtering must be done on categories, not electrical parameters.
- Catalog reads are edge-cached for up to 7 days (Cloudflare + LiteSpeed), so data may be stale.
- No rate limits are published and none were observed, but the host sits behind Cloudflare and Wordfence, either of which may throttle without a standard header.
- Errors use the WordPress envelope {code, message, data:{status}}, not RFC 9457 problem+json.
- No idempotency support: repeated cart mutations are not safe to retry.
